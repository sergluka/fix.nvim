*fix.nvim.txt*                  FIX protocol support for Neovim

==============================================================================
CONTENTS                                                        *fix.nvim*

fix.nvim is a Neovim plugin for reading FIX protocol logs. It parses FIX
messages with tree-sitter, resolves tags and enum values from FIX dictionaries,
and decorates buffers with virtual text.

==============================================================================
REQUIREMENTS                                           *fix.nvim-requirements*

- Neovim 0.11 or newer.
- nvim-treesitter.
- tree-sitter-fix, installed with:
>
    :TSUpdate fix
<
- xml2lua.
- mega.cmdparse.
- mega.logging.
- snacks.nvim, optional, for |:FIX-picker|.
- neo-tree.nvim, optional, for |:FIX-tree|.

On very large files, Neovim's tree-sitter highlighting can freeze the UI when
jumping into unparsed regions. That is independent of fix.nvim. Disable
highlighting for those buffers with:
>
    :lua vim.treesitter.stop(0)
<
fix.nvim annotations continue to work because the plugin parses asynchronously
and renders the viewport first.


==============================================================================
INSTALLATION                                           *fix.nvim-installation*

Example for lazy.nvim:
>
    {
      "sergluka/fix.nvim",
      dependencies = {
        "nvim-treesitter/nvim-treesitter",
        "manoelcampos/xml2lua",
        "ColinKennedy/mega.cmdparse",
        "ColinKennedy/mega.logging",
        "folke/snacks.nvim", -- optional
        "nvim-neo-tree/neo-tree.nvim", -- optional
      },
      build = { "rockspec", ":TSUpdate fix" },
      opts = {},
    }
<
The rockspec is used so lazy.nvim can install Lua dependencies. Plugin code is
loaded from the Neovim runtimepath.


==============================================================================
USAGE                                                         *fix.nvim-usage*

fix.nvim registers the `fix` filetype for these defaults:

- Extensions: `fix`, `fixlog`.
- Pattern: `.*%.fix.txt`.

When a buffer has `filetype=fix`, fix.nvim attaches automatically and annotates
the visible viewport first. Off-screen lines warm the parse/decode cache in
background batches. Message validation runs alongside it and reports problems
as diagnostics; see |fix.nvim-validation|.

No keymaps are set by default. Use |fix.nvim-keymaps| for suggested mappings.


==============================================================================
COMMANDS                                                   *fix.nvim-commands*

                                                              *:FIX*
The `:FIX` command exposes the user-facing plugin actions.

                                                              *:FIX-help*
`:FIX --help`
    Show command help generated by mega.cmdparse.

                                                       *:FIX-annotations*
`:FIX annotations [all|tag|value|title|message|group]`
    Toggle all annotations or one annotation scope. `message` is a legacy alias
    for `title`.

    `all`, or no argument, toggles every annotation scope off. Running it again
    restores the per-scope state from the last `setup()` call.

                                                          *:FIX-picker*
`:FIX picker`
    Open the fields picker. Requires snacks.nvim.

                                                            *:FIX-tree*
`:FIX tree`
    Open the FIX message tree. Requires neo-tree.nvim and source registration:
>
        require("neo-tree").setup({
          sources = { "filesystem", "buffers", "git_status", "fix.neo_tree" },
        })
<
    `:Neotree fix` opens the same source. Summaries in the current FIX-buffer
    viewport are added first. The rest of the buffer is scanned in
    `render.lines_per_batch` background batches; scrolling adds missing
    summaries in the new viewport without restarting that scan. A bottom row
    shows scan progress until all summaries have been added. Message fields and
    repeating groups are added only when their message is expanded; repeating-
    group instances start collapsed. Opening the tree expands only the path to
    the field under the cursor.

    `<CR>` opens or toggles a node, `<Space>` toggles it, `C` collapses the
    current branch, and `z` collapses all loaded branches. `y` yanks the
    displayed label to the active Vim register. `gx` opens online documentation
    for a field or repeating-group count tag. Moving across fields in the FIX
    buffer selects the matching node without stealing focus. The source follows
    the last active FIX buffer and inherits neo-tree's global window position.

                                                          *:FIX-browse*
`:FIX browse`
    Open the Onixs documentation page for the tag under the cursor.

                                                      *:FIX-dictionary*
`:FIX dictionary {path}`
    Register a custom FIX dictionary XML file or repository directory for the
    current Neovim session. See |fix.nvim-dictionaries|.

                                                            *:FIX-yank*
`:FIX yank [--reg={register}]`
    Yank annotated FIX data.

    Characterwise visual ranges yank selected annotated fields. Linewise ranges
    yank selected messages. Without a range, the command yanks the current field
    or message according to the yank helper behavior.

                                                  *:FIX-lsp-toggle*
`:FIX lsp toggle`
    Turn the LSP features — diagnostics, fixes and dictionary hover — on or
    off for every FIX buffer. See |fix.nvim-validation|.

                                                     *:FIX-cache-clear*
`:FIX cache clear`
    Drop in-memory and on-disk cache entries for the current file, then
    re-render the buffer.

CONFIGURATION                                         *fix.nvim-configuration*

Call `require("fix").setup()` or pass `opts = {}` through a plugin manager.
These are the defaults:
>
    require("fix").setup({
      -- Used when BeginString, tag 8, is missing or unknown.
      -- Examples: "FIX.4.0", "FIX.4.4", "FIX.5.0SP2", "FIXT.1.1".
      fallback_version = "FIX.4.4",

      -- Custom dictionaries keyed by BeginString/FIX version.
      -- `tags` can be used with or without `path` to add Lua decoders.
      dictionaries = {},

      -- Filetype detection rules passed to vim.filetype.add().
      ft = {
        extensions = { "fix", "fixlog" },
        pattern = { ".*%.fix.txt" },
      },

      annotate = {
        group = {
          path = {
            enabled = true, -- Show group paths in field labels.
          },
          highlight = {
            enabled = true, -- Highlight grouped fields.
            target = "both", -- "raw", "annotation", or "both"
            -- Alternate colors by depth and entry.
            palette = {
              "FixGroupDepth1A",
              "FixGroupDepth1B",
              "FixGroupDepth2A",
              "FixGroupDepth2B",
              "FixGroupDepth3A",
              "FixGroupDepth3B",
            },
          },
        },
        tag = {
          enabled = false,
          formatter = function(field)
            return require("fix.formatters.tag").default(field)
          end,
        },
        value = {
          enabled = false,
          formatter = function(field)
            return require("fix.formatters.value").default(field)
          end,
        },
        title = {
          enabled = true,
          position = "above", -- "above" | "below" | "front" | "replace" | "replace_front"
          route = {
            enabled = true,
            mode = "direction", -- "direction" | "sender" | "pair"
            palette = {
              "FixRoute1",
              "FixRoute2",
              "FixRoute3",
              "FixRoute4",
              "FixRoute5",
              "FixRoute6",
              "FixRoute7",
              "FixRoute8",
            },
            overrides = {
              -- { sender = "CLIENT1", target = "*", highlight = "FixClientSend" },
            },
            resolver = nil, -- function(route, message) return "HighlightGroup" end
          },
          formatter = function(message)
            return require("fix.formatters.title").default(message)
          end,
        },
      },

      cache = {
        persist = {
          enabled = true,
          max_files = 20,
          max_bytes = 100 * 1024 * 1024,
          dir = nil, -- stdpath("cache") .. "/fix.nvim"
        },
      },

      render = {
        debounce_ms = 80,
        lines_per_batch = 500,
        viewport_margin = 50,
      },

      lsp = {
        enabled = true,
        validate = {
          enabled = true,
          debounce_ms = 200,
          rules = {
            begin_string = { enabled = true },
            body_length = { enabled = true },
            checksum = { enabled = true },
          },
        },
        hover = {
          enabled = true,
        },
      },

      tree = {
        summary = {
          formatter = function(message)
            return require("fix.formatters.tree.summary").default(message)
          end,
        },
        field = {
          formatter = function(field)
            return require("fix.formatters.tree.field").default(field)
          end,
        },
        group = {
          formatter = function(group, field)
            return require("fix.formatters.tree.group").default(group, field)
          end,
        },
      },
    })
<
Omit a `formatter` field to use the built-in formatter. The wrapped
`require(...)` form above is safe for plugin-manager `opts` tables because the
module is loaded only when the formatter runs.

`fallback_version` must refer to a bundled or configured dictionary.
`FIXT.1.1` resolves through `FIX.5.0SP2` unless explicitly registered.

                                                    *fix.nvim-formatters*
Custom formatters should be pure functions of the provided message or field.
Formatter output is cached by line hash and reused across identical lines and
buffers. Formatters that read `message.lineno`, buffer state, or other external
state can produce stale annotations.

Field formatters return:
>
    { text = "display text", highlight = "HighlightGroup" }
<
Tree summary, field, and group formatters may return one positional chunk:
>
    { "display text", "HighlightGroup" }
<
or a list of chunks:
>
    {
      { "decoded name", "Identifier" },
      { " = decoded value", "String" },
    }
<
The single-chunk form remains supported. The built-in tree formatters show
decoded names and values first, with raw tags and enum values as metadata.
Like a title formatter, the summary formatter receives a `Message` and can use
`message:field(tag)`. The field formatter receives a `Field`. The group
formatter receives `(group, field)`: a typed `FixTreeGroup` and its repeating-
group count field, such as `NoMDEntries (268)`. Setting a tree formatter fully
replaces the default formatter for that node type.

The built-in tree formatters use `FixTreeIcon`, `FixTreeName`, `FixTreeValue`,
`FixTreeMeta`, `FixTreeOperator`, and `FixTreeGroup`. These are default-linked
to `Special`, `Identifier`, `String`, `Comment`, `Operator`, and `Type`
respectively, and may be overridden like normal highlight groups.
Title formatters return:
>
    { { { "display text", "HighlightGroup" } } }
<
Title formatters receive the parsed message and may also call:
>
    message:route()
    message:route_key()
    message:route_highlight()
<
`message:route()` returns `{ sender, target }` from FIX tags `49` and `56`.
`message:route_highlight()` applies structured route rules and deterministic
palette fallback, so custom formatters can reuse route colors without using the
default `sender=>target` text. Route `overrides` match structured values; use
`*` as a wildcard for `sender` or `target`.

                                                   *fix.nvim-cache*
The persistent cache lives at `stdpath("cache")/fix.nvim` unless
`cache.persist.dir` is set. Set `cache.persist.enabled = false` to keep all
cache data in memory only.

Cache rotation deletes the oldest `.mpack` files until both enabled limits,
`max_files` and `max_bytes`, are satisfied. When persistence is enabled, at
least one rotation limit must remain enabled.

                                                   *fix.nvim-rendering*
Rendering is viewport-first. The visible region, plus `viewport_margin` lines
above and below it, is annotated after the edit debounce. The rest of the
buffer warms the parse/decode cache in `lines_per_batch` chunks.

Off-screen extmarks are not kept around. Annotations are re-applied as you
scroll, which keeps large buffers responsive.

Set `annotate.title.position = "replace"` to conceal each FIX message line
and show the formatted message title in its place. This mode uses Neovim
conceal, so FIX buffers set `conceallevel=2`. Use `"replace_front"` to keep
other lines replaced while showing the active line as raw FIX with normal field
annotations and the title at the front.

`annotate.message` is kept as a deprecated alias for `annotate.title`. Using it
emits a warning; if both are set, `annotate.title` wins.

                                                   *fix.nvim-validation*
Validation runs as a language server inside Neovim, started on demand; nothing
extra needs installing. Problems appear as ordinary diagnostics, so signs,
`]d`/`[d` and |vim.diagnostic.setqflist()| work as usual, and repairs appear as
code actions applied by Neovim's LSP client, so undo behaves normally.

Three rules ship built in. `begin_string` reports a line that parses as
`tag=value` pairs but carries no BeginString — a dumped repeating group, a
truncated line — as "Not a FIX message". `body_length` checks BodyLength (tag
9) and `checksum` checks CheckSum (tag 10); both also report the field missing
entirely. The latter two are linked, because correcting BodyLength changes the
bytes CheckSum covers: a message wrong in both places offers one "Fix
BodyLength and CheckSum" action. Field separators are normalised, so `|`, `^`
and SOH logs validate the same.

Rules run in tiers, lowest first, and a tier that reports anything stops the
ones below it: a line that is not a FIX message has no BodyLength worth
complaining about. `begin_string` is tier 0, everything else defaults to tier
1. Set `tier` on a rule of your own to slot it in.

Code action kinds:
>
    quickfix        repair the message under the cursor or in the selection
    source.fixAll   repair every broken message in the buffer, as one undo step
<
`gra` (or |vim.lsp.buf.code_action()|) offers both. To bind "fix all" directly:
>lua
    vim.keymap.set("n", "<leader>ff", function()
      vim.lsp.buf.code_action({
        context = { only = { "source.fixAll" } },
        apply = true,
      })
    end)
<
`lsp.validate.rules` maps a rule id to its settings. A built-in rule accepts
`enabled` and `severity`; set the entry to `false` to switch it off. An entry
with a `check` function defines a rule of your own, taking its id from the key:
>lua
    lsp = {
      validate = {
        rules = {
          checksum = false,
          unknown_tags = {
            severity = vim.diagnostic.severity.WARN,
            check = function(ctx)
              local out = {}
              for _, field in ipairs(ctx.message:list_fields()) do
                if field.tag_text == nil then
                  out[#out + 1] = {
                    col = field.tag_start,
                    end_col = field.tag_end,
                    message = "Unknown tag " .. field.tag,
                  }
                end
              end
              return out
            end,
          },
        },
      },
    }
<
Besides `check`, a rule entry accepts `name`, `severity` and `tier`.

`check` receives `ctx` with `buf`, `lnum` (0-based), `line`, `message`, `opts`,
and a `scratch` table shared by every rule on that line. It returns a list of
diagnostics with 0-based byte columns `col` and `end_col`, a `message`, an
optional `severity` (ERROR by default) and `code` (the rule id by default), and
optional `fixes`. Each fix is `{ title, edits }` where an edit is
`{ lnum?, col, end_col, new_text }`; `col == end_col` inserts. Fixes may be
shared between diagnostics — a shared fix is offered only once.

A rule that errors is reported once and skipped; the other rules keep running.

Rule scope is per message. Session-level rules that need the whole message
stream are not supported yet, and `scope = "session"` is rejected.

The same server answers |vim.lsp.buf.hover()|: the float shows the field's
decoded name, tag, FIX data type, the dictionary description, the current
value with its enum meaning, the repeating-group path when the field sits
inside one, and an onixs.biz reference link. For MsgType (tag 35) it adds the
message-type description from the FIX repository. Custom quickfix-style
dictionaries carry names but no descriptions, so their hovers are shorter.
`lsp.hover.enabled = false` turns hover off on its own;
`lsp.validate.enabled = false` keeps hover but silences the diagnostics;
|:FIX-lsp-toggle| (or `lsp.enabled = false`) turns the whole subsystem off.
Example mapping:
>lua
    vim.keymap.set("n", "K", vim.lsp.buf.hover, { buffer = true })
<
Diagnostic display is not configured here; use |vim.diagnostic.config()| — with
one exception. With `annotate.title.position` set to `"replace"` or
`"replace_front"` the message line is concealed, which leaves it no display
width for virtual text to attach to: |vim.diagnostic| would drop its text onto
the row below, or lose it entirely. In those positions the message title
carries the diagnostics itself, drawn right after it:
>
    20251026-09:00:02 CLIENT1=>BROKER1 NewOrderSingle   ■ CheckSum is 001, expected 213
<
Severity picks the highlight group, `DiagnosticVirtualTextError` and friends.

Where that happens, `virtual_text` is switched off for this plugin's diagnostic
namespace so the same message is not drawn twice; the global
|vim.diagnostic.config()| and every other language server are untouched. On the
revealed cursor line in `"replace_front"` the raw message is visible, so
`virtual_text` keeps working there and diagnostics render normally. Underlines
are invisible on a concealed line either way; the sign column still works.

A buffer with no file name gets code actions but no diagnostics: its document
URI is `file://`, which does not map back to the buffer. Write the buffer to a
file to get diagnostics.

DICTIONARIES                                           *fix.nvim-dictionaries*

fix.nvim ships bundled FIX dictionaries from `FIX.4.0` through `FIX.5.0SP2`,
plus `FIXT.1.1`.

Dictionary selection is based on tag 8, `BeginString`. A custom dictionary
keyed by that version wins. Otherwise the bundled dictionary is used. If tag 8
is missing or unknown, `fallback_version` is used.

Configure dictionaries in `setup()`:
>
    require("fix").setup({
      dictionaries = {
        ["FIX.4.4"] = {
          path = "xml/custom/binance/spot-fix-oe.xml",
          mode = "quickfix", -- "auto" | "quickfix" | "repository"
          ---@type table<integer, FixTagDecoder>
          tags = {
            [25035] = function(field, _ctx)
              return {
                tag_text = "MessageHandling",
                value_text = ({ ["1"] = "UNORDERED", ["2"] = "SEQUENTIAL" })[field.value],
              }
            end,
          },
        },
        ["FIX.4.2"] = "xml/custom/coinbase/order-entry/FIX42-prod-sand.xml",
      },
    })
<
`dictionaries` may also be a list of paths or `{ path, mode }` entries when
each entry infers a different FIX version. If two entries infer the same
version, use explicit version keys.

Custom tag decoders receive the parsed `field` after XML dictionary lookup and
`ctx = { version, fields, dictionary }`. Return `tag_text` and/or `value_text`
to replace the XML-derived annotation text; return `nil` for either key to keep
the existing value. A pathless entry such as `dictionaries["FIX.4.4"] =
{ tags = ... }` overlays the bundled dictionary for that version. The
`FixTagDecoder` alias is available for LuaLS annotations.

Register a dictionary at runtime:
>
    :FIX dictionary xml/custom/binance/spot-fix-oe.xml
<
`FIX dictionary` accepts a QuickFIX-style XML file or a FIX Repository
directory containing `Fields.xml` and `Enums.xml`. Repository dictionaries can
also include `Messages.xml`, `MsgContents.xml`, and `Components.xml` to enable
repeating group paths. Runtime registration lasts until another custom
dictionary is registered for the same version, `setup()` is run again, or
Neovim exits.

KEYMAPS                                                   *fix.nvim-keymaps*

No keymaps are set by default.

Suggested buffer-local mappings:
>
    local fix = require("fix")

    local function map(lhs, rhs, desc)
      vim.keymap.set("n", lhs, rhs, {
        buffer = true,
        desc = "fix: " .. desc,
      })
    end

    map("<localleader>t", function()
      fix.annotate_toggle("title")
    end, "toggle title annotation")

    map("<localleader>T", function()
      fix.annotate_toggle("all")
    end, "toggle all annotations")

    map("<localleader>x", function()
      fix.browse_tag_online()
    end, "open online tag docs")

    vim.keymap.set("n", "<localleader>y", function()
      return fix.operator_yank_register("+")
    end, {
      expr = true,
      buffer = true,
      desc = "fix: yank target",
    })

    vim.keymap.set("x", "<localleader>y", function()
      fix.yank("+")
    end, {
      buffer = true,
      desc = "fix: yank selection",
    })

    vim.keymap.set("n", "<localleader>yy", function()
      return fix.operator_yank_register("+") .. "_"
    end, {
      expr = true,
      buffer = true,
      desc = "fix: yank line",
    })

    map("<localleader><localleader>", function()
      require("fix.snacks").open()
    end, "open field picker")
<
Use `fix.operator_yank_register()` without an argument to write to Vim's
default unnamed register. Pass `"+"` or another register name to make the
mapping use a specific register by default.

Navigation mappings can be built with nvim-treesitter-textobjects:
>
    local ok, ts_move = pcall(
      require,
      "nvim-treesitter-textobjects.move"
    )
    if not ok then
      ts_move = require("nvim-treesitter.textobjects.move")
    end

    local function ts_map(lhs, method, query, desc)
      vim.keymap.set({ "n", "x", "o" }, lhs, function()
        ts_move[method](query)
      end, { buffer = true, desc = "fix: " .. desc })
    end

    ts_map("]]", "goto_next_start", "@field", "next field start")
    ts_map("[[", "goto_previous_start", "@field", "previous field start")
    ts_map("]}", "goto_next_end", "@field", "next field end")
    ts_map("[{", "goto_previous_end", "@field", "previous field end")

    ts_map("]m", "goto_next_start", "@message", "next message start")
    ts_map("[m", "goto_previous_start", "@message", "previous message start")
    ts_map("]M", "goto_next_end", "@message", "next message end")
    ts_map("[M", "goto_previous_end", "@message", "previous message end")

    ts_map("]g", "goto_next_start", "@comment", "next comment start")
    ts_map("[g", "goto_previous_start", "@comment", "previous comment start")
    ts_map("]G", "goto_next_end", "@comment", "next comment end")
    ts_map("[G", "goto_previous_end", "@comment", "previous comment end")
<
With the yank mapping above, `<localleader>y` behaves like a Vim operator.
Operator targets such as `]]` must be available in operator-pending mode, so
the textobject mappings use `{ "n", "x", "o" }`.


==============================================================================
LIMITATIONS                                             *fix.nvim-limitations*

Due to a Neovim limitation, virtual lines above the first buffer line are not
displayed. If the first message title is hidden, use one of these workarounds:

- Add an empty line at the beginning of the file.
- Press `<C-b>` after opening the file.
- Set `annotate.title.position = "below"`, `"front"`, `"replace"`, or `"replace_front"`.

DEVELOPMENT                                             *fix.nvim-development*

Integration tests run inside a Podman container. The image includes Neovim,
the tree-sitter-fix parser, and all Lua dependencies at pinned commit SHAs, so
tests do not need network access at runtime.
>
    ./bin/test-integration
    ./bin/test-integration --rebuild
    ./bin/test-integration --filter annotate
<
Host-side linting:
>
    stylua --check .
    luacheck .
<

LUA API                                                       *fix.nvim-api*

                                                        *fix.setup()*
`require("fix").setup({opts})`
    Configure fix.nvim. See |fix.nvim-configuration|.

                                                *fix.annotate_toggle()*
`require("fix").annotate_toggle([scope])`
    Toggle annotations for `scope`, one of `"all"`, `"tag"`, `"value"`,
    `"title"`, or `"group"`. `"message"` is accepted as a legacy alias for
    `"title"`. Nil behaves like `"all"`.

                                              *fix.browse_tag_online()*
`require("fix").browse_tag_online()`
    Open online documentation for the FIX tag under the cursor.

                                                 *fix.use_dictionary()*
`require("fix").use_dictionary(path)`
    Register a custom dictionary at runtime and re-render open FIX buffers.
    Returns the registered dictionary source.

                                                      *fix.lsp_toggle()*
`require("fix").lsp_toggle()`
    Turn the LSP features (diagnostics, fixes, hover) on or off for every FIX
    buffer.

                                              *fix.validate.register()*
`require("fix.validate").register(rule)`
    Add or replace a validation rule at runtime and revalidate open buffers.
    `rule` needs an `id` and a `check` function; see |fix.nvim-validation|.
    Unlike rules declared in `lsp.validate.rules`, registered rules survive a
    later `setup()` call. Returns the rule.

                                                    *fix.cache_clear()*
`require("fix").cache_clear()`
    Clear cache data for the current FIX file and re-render the buffer.

                                                           *fix.yank()*
`require("fix").yank([register], [selection])`
    Yank annotated fields or messages. `selection` is normally supplied by the
    command wrapper or visual mapping.

                                         *fix.operator_yank_register()*
`require("fix").operator_yank_register([register])`
    Return the `g@` operator expression used by mappings. The optional register
    becomes the default register for the operator action.

                                                        *fix.snacks.open()*
`require("fix.snacks").open()`
    Open the optional snacks.nvim field picker.

                                                      *fix.neo_tree.open()*
`require("fix.neo_tree").open()`
    Open the optional neo-tree FIX source. The source must be registered as
    `fix.neo_tree` in neo-tree's `sources` list.
