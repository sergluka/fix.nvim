# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Neovim plugin for viewing FIX protocol messages. Runtime dependencies: `xml2lua`, `mega.cmdparse`, `mega.logging`, optional `snacks.nvim`, plus the [tree-sitter-fix](https://github.com/sergluka/tree-sitter-fix) parser (master branch only).

## Commands

- Run integration tests: `./bin/test-integration` (builds Podman image on first run, then runs the full MiniTest suite — 221 cases inside `tests/integration/`). Single spec: `./bin/test-integration --filter annotate` (resolves to `tests/integration/test_<name>.lua` via `MiniTest.run_file`). Force image rebuild: `./bin/test-integration --rebuild`. Requires Podman >= 5.x.
- Lint: `luacheck .` (config in `.luacheckrc` — Lua 5.1, `vim` global).
- Format: `stylua --check .` (pinned to stylua 2.3.0 — match locally; CI enforces this exact version).
- CI (`.github/workflows/ci.yml`) runs `stylua --check .` + `luacheck` on host and the Podman integration suite on every push/PR.

## Architecture

The plugin decorates FIX-message buffers with extmark-based virtual text; it does not modify the buffer. Data flows in one direction per render: `FileType/BufWinEnter → render.attach; on_lines → render (debounce/warm-up) → cache → document.build_line → annotate.apply → extmarks`.

- `plugin/fix.lua` — entrypoint loaded by Neovim. Registers the tree-sitter parser config, builds the `:FIX` user command via `mega.cmdparse`, and dispatches subcommands (`annotations`, `picker`, `browse`, `dictionary`, `yank`, `cache`) to `require("fix")`.
- `ftplugin/fix.lua` — buffer-local options for `filetype=fix` (conceallevel, iskeyword excluding `|` and `=`, `# %s` commentstring).
- `lua/fix/init.lua` — `setup()` deep-merges user opts over `default_settings`, prepares `opts.dictionaries`, validates `fallback_version` against bundled + custom dictionaries, registers filetype patterns/extensions, and wires an autocmd group `fix-decorate` that calls `Render.attach` on `FileType`/`BufWinEnter` and `Render.refresh_viewport` on scroll/resize. Also holds `opts_initial` so toggling "all off -> all on" restores the user's per-scope enabled flags. Re-running `setup()` drops the render cache unless `fallback_version` or dictionaries changed, then re-renders all open buffers. Exposes `cache_clear()` for `:FIX cache clear` and `use_dictionary(path)` for `:FIX dictionary <path>`. New options blocks: `dictionaries`, `cache.persist`, `render`, and `lsp` (`lsp.enabled` gates the whole subsystem, `lsp.validate.*` the diagnostics, `lsp.hover.enabled` the hover; `:FIX lsp toggle` flips `lsp.enabled`).
- `lua/fix/document.lua` — tree-sitter traversal. `build_line(buf, lnum)` is the primary incremental path: parses the single line, checks the two-layer cache, and calls `decode()` only on cache misses. `iter_messages` is a thin whole-buffer wrapper over `build_line` kept as public API; the snacks picker streams via `build_line` directly and yank goes through `get_field_under_cursor`. Detects the dictionary version from tag 8 (BeginString). Duplicate tags within a message are keyed as `tag:index` in a side-slot (groups are not yet first-class — see TODO in `init.lua`).
- `lua/fix/dictionary.lua` — `Dictionary.load(version)` resolves either a configured custom dictionary or bundled `xml/<version>/Base/{Fields,Enums}.xml`, parses it via `xml2lua`, and caches by dictionary source. Custom dictionaries are configured by `Dictionary.prepare/apply/configure` from setup or registered ad hoc with `Dictionary.register(path)`; supported modes are `auto`, `quickfix`, and `repository`. `FIXT.1.1` transparently resolves to `FIX.5.0SP2` unless explicitly registered. Messages are looked up via tag-35 enum (`dict:message(value)`).
- `lua/fix/annotate.lua` — writes extmarks into namespace `fix-protocol`: inline virt_text after the tag, inline virt_text after the value, and message titles as `virt_lines` (`above`/`below`) or inline virt_text at column 0 (`front`). `build_payload` assembles a `FixRenderPayload` for a message (all kinds, enabled flags not applied). `payload_for` wraps it with the render cache. `apply` does a point-clear on the message line then sets only the extmarks whose kind is currently enabled — so toggling annotation scopes never invalidates cached payloads. In the `replace`/`replace_front` positions the line is concealed and therefore has no display width for `eol` virtual text, so `apply` appends the line's diagnostics to the title overlay chunks (copied, never mutating the cached payload). Titles with `position="below"` anchor on the message line via `virt_lines_above=false`.
- `lua/fix/cache.lua` — two-layer in-memory cache, both layers keyed by the same line-content hash (`M.key(line_text)`, shared across buffers): a semantic layer and a render-payload layer. `drop_render()` evicts only the render layer, used on re-setup.
- `lua/fix/scan.lua` — the viewport-first walking mechanism, shared by the annotation renderer and the neo-tree source so neither owns a private copy: `viewport_ranges(buf)`, a covered-line range set (`cover`/`pending`/`advance`), and `walk(opts)` — a background walker that visits one `lines_per_batch` batch per 10 ms tick, retries a batch whose `on_batch` returns `false` (non-authoritative parse), and calls `on_complete` at the end of the buffer. Consumers supply `on_batch`/`on_complete`; `walk:rewind(lnum)` is pure Lua so `on_lines` can call it from a fast context, `walk:resume()` restarts the ticking from a scheduled one.
- `lua/fix/render.lua` — extmark renderer driving a `Scan` walk. `attach(buf)` hooks `nvim_buf_attach` (`on_lines`) with an 80 ms debounce. The visible viewport (± `viewport_margin`) is annotated immediately and re-applied on scroll (`refresh_viewport`); the background walk only fills the parse/decode cache and never places off-screen extmarks, so the placed-mark count is always bounded by what's been viewed. Unlike the tree, coverage is tracked per line as a content hash (`state.rendered`) so an edit repaints exactly the changed lines; the slot also holds the identity of the line's diagnostics table. `M.diagnostics_in_title()` is the single source of truth for "titles carry diagnostics" — the validator reads it both to trigger a viewport repaint after publishing (the renderer debounces faster, so it always paints a line before its diagnostics exist) and to decide how to configure its diagnostic namespace. `flush`/`flush_all_sync` drain pending writes on `BufUnload`/`VimLeavePre`.
- `lua/fix/neo_tree/` — optional neo-tree source (`init.lua` scan/state, `commands.lua`, `components.lua`, `items.lua`). It is a `Scan` consumer: summaries stream in viewport-first via `Document.summary_line`, the rest of the buffer follows in the background walk, and coverage is a range set rather than per-line hashes. neo-tree modules are required lazily so `require("fix.neo_tree")` still loads when neo-tree is absent.
- `lua/fix/validate/` — validation and repair. `init.lua` is the engine: a third `Scan` consumer with its own `nvim_buf_attach`/debounce, holding per-line diagnostics plus the fixes they carry (`refresh_line`, `lines_with_diagnostics`, `fix_edits`, `is_idle` for tests). `lsp.lua` is a thin in-process LSP server (`vim.lsp.start` with a function `cmd`, `positionEncoding="utf-8"`) that answers `textDocument/codeAction` with `quickfix` and `source.fixAll` actions, and `textDocument/hover` with dictionary-backed tag info (markdown built by `validate/hover.lua`; `dictionary.lua` also parses Messages.xml into `MessageDef`s exposed via `dict:message_def`; gated by `lsp.hover.enabled` at request time — `hoverProvider` is always advertised because initialize runs once per client; `lsp.validate.enabled = false` stops the walk and diagnostics but keeps the attach, so hover survives). Diagnostics go out through `dispatchers.notification("textDocument/publishDiagnostics", …)` — never `vim.diagnostic.set`, which skips the client bookkeeping `vim.lsp.buf.code_action` reads back (`user_data.lsp`). Unnamed buffers are skipped when publishing: their URI is `file://`, which `vim.uri_to_bufnr` turns into a fresh buffer every call. When titles carry the diagnostics, the engine also suppresses the stock `virtual_text` handler for its own namespace only — `false`, or under `replace_front` a function narrowing the user's own config with `current_line = true` (namespace options replace global ones outright rather than merging, so narrowing instead of replacing is what keeps their prefix/format/severity) — otherwise Neovim would draw them a second time, inline, over the title. The key is cleared by assigning through `vim.diagnostic.get_namespace(ns).opts`, since `vim.diagnostic.config()` can only add or overwrite. `rules/init.lua` is the registry (built-ins, `lsp.validate.rules` from setup, runtime `register()`; bucketed by scope so session-level rules land additively) and orders rules by `tier`, lowest first — the engine stops descending once a tier has produced a diagnostic, so a line that isn't a FIX message never reaches the content rules. `rules/structure.lua` holds tier 0: `begin_string` reports a `tag=value` run with no BeginString as "Not a FIX message". `rules/integrity.lua` implements `body_length` and `checksum` from field spans with as-if-SOH separator normalisation; both rules share one repair, so a message wrong in both places offers a single action. This is the only code path that mutates a buffer, and only the LSP client applies it.
- `lua/fix/persist.lua` — mpack-based disk cache under `stdpath("cache")/fix.nvim`. Keyed by absolute path + dict fingerprint; stale entries are invalidated automatically. LRU eviction at `max_files=20`. Writes are atomic (tmp file + rename). Exposed to users via `:FIX cache clear` → `M.delete(buf)`.
- `lua/fix/field.lua` / `lua/fix/message.lua` — plain data classes reconstructed from cached semantic tables. `Message` exposes route helpers from tags 49/56 for formatter use.
- `lua/fix/formatters/{tag,value,message}.lua` — default formatters returning `{text, highlight}` chunks for fields or Neovim `virt_lines`-style title payloads for messages. User-supplied formatters must match these shapes; they're invoked from `annotate.lua`.
- `lua/fix/snacks.lua` — optional picker UI (requires `snacks.nvim`).
- `lua/fix/yank.lua` — smart yank helpers used by `:FIX yank [--reg=<r>]` and the operatorfunc API.
- `lua/fix/consts.lua` — `FixVersion` enum used as the canonical internal version key (tree-sitter BeginString strings are mapped to it in `document.lua`).
- `queries/fix/{highlights,textobjects}.scm` — tree-sitter queries shipped with the plugin.
- `xml/FIX.*` — vendored FIX Repository data ((c) FIX Protocol Limited, used under licence — see `plugin/fix.lua` header and `THIRD_PARTY_LICENSES.txt`). Do not regenerate by hand.
- `xml/custom/` — vendored public broker dictionaries used by tests (Coinbase Exchange and Binance Spot); source/terms are recorded in `xml/custom/README.md` and `THIRD_PARTY_LICENSES.txt`.
- `samples/` — `.fix` files for manual testing in Neovim.
- `tests/integration/` — MiniTest specs (`test_dictionary`, `test_annotate`, `test_commands`, `test_lifecycle`, `test_edge_cases`, `test_cache`, `test_persist`, `test_picker`, `test_validation`) — driven by `tests/integration/run.lua`. Bootstrap via `tests/integration/minimal_init.lua`; shared helpers in `tests/integration/helpers.lua` (key patterns: `wait_annotated` polls `require("fix.render").is_idle()`, and `load_fixture` asserts extmarks afterwards); fixtures under `tests/integration/fixtures/`. The whole suite runs inside the Podman image built from `Containerfile`.
- `Containerfile` — multi-stage Podman image: builder compiles `tree-sitter-fix` and clones Lua deps at hardcoded SHAs; runtime carries Neovim 0.12.0 + `fix.so` + `/opt/deps/*`. SHAs are string literals (no `ARG`).
- `bin/test-integration` — wrapper that builds the image on demand and runs the suite; supports `--rebuild` and `--filter <pattern>`.

## Conventions

- Lua 5.1, 4-space indentation (configured in `stylua.toml`). Keep `---@class` / `---@field` annotations in sync with `FixOpts` in `init.lua` when adding options.
- New options must be added to `default_settings` in `init.lua` AND to the `FixOpts` annotation; downstream code reads them through the merged `M.opts`.
- User-facing configuration samples are duplicated in `README.md`, `doc/fix.nvim.txt`, and `lua/fix/init.lua`; when changing defaults or option shape, update or verify all three.
- New user-facing features get a subsection in the README `## Features` section (short description, screenshot in `media/` when the feature is visual — existing shots are dark-theme, 1600px wide, cropped to content).
- When adding a FIX version: drop `Fields.xml`/`Enums.xml` under `xml/FIX.<ver>/Base/`, add it to `Consts.FixVersion` and to the `versions` maps in both `document.lua` and `init.lua`'s `browse_tag_online`, and extend the version list in `tests/integration/test_dictionary.lua`.
- Tests should load dictionaries via `Subject.load(...)` rather than stubbing XML.
